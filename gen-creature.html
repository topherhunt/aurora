LOD tiers

        

        

          Click a tier to load it into the preview; the camera holds its angle across the swap, so
          the silhouette is comparable frame to frame. Tiers belong to the mesh candidate they were
          decimated from -- selecting a different candidate shows that one's ladder.
        

        

          A tier that stops well short of its target is not a bug in the decimator: seam and
          boundary vertices are pinned, so the reduction ceiling is a direct measurement of how
          few, how large and how well-closed this mesh's UV islands are -- the same property that
          decides whether the texture survives 128px.
        

      

    


    

      
this bench

      

        Every orange button spends real money and nothing fires on its own. The image step bills
        OpenRouter (~$0.015); the mesh, rig and animation steps bill Tripo credits at $0.01 each.
        rig-check is free and is the only way to find out a mesh
        cannot be rigged without paying 25 credits to discover it -- always run it first.
      

      

        Working files land in tools/creatures/work/<id>/ (gitignored). Tripo's result
        URLs expire, so each step downloads its output to disk before returning; the task ids in
        state.json are the only handle on work already paid for.
      

      

        Why P1 is the default. The texture panel is the real gate on this pipeline,
        not the triangle count. A decimated mesh gets auto-unwrapped into a scatter of small UV
        islands, and at 128px the small ones vanish while bilinear filtering bleeds neighbours
        across every seam. P1 generates native quad topology with coherent edge flow, so the islands
        come out fewer and larger and survive the downrez. Judge a candidate on the panel it ships
        at, never on Tripo's 2048 source.

bone names

      
Mixamo's convention throughout: side is a prefix word (LeftArm, not Arm.L), the first of a chain carries no number (Spine, Spine1, Spine2), thigh is UpLeg and shin is Leg, upper arm is Arm and forearm is ForeArm.

      
Reading the trees: a run joined by ─ is an unbranched chain, and anything that has children of its own nests onto its own line. So the neck and both shoulders hang off Spine2, the last spine bone — not off Spine. In Blender only the unbranched runs are connected bones, and that is what rig.blend sets up for you: a child whose head already sits on its parent's tail gets connected, and every branch point (both shoulders, both UpLegs, the tail) stays disconnected, because snapping it would move the joint and shift the bind. That is also exactly where an IK chain should stop.


      

        biped — the Mixamo skeleton, verbatim
        
Hips
├─ Spine
│  └─ Spine1
│     └─ Spine2
│        ├─ Neck ─ Head ─ HeadTop_End
│        ├─ LeftShoulder  ─ LeftArm  ─ LeftForeArm  ─ LeftHand  ─ fingers
│        └─ RightShoulder ─ RightArm ─ RightForeArm ─ RightHand ─ fingers
├─ LeftUpLeg  ─ LeftLeg  ─ LeftFoot  ─ LeftToeBase  ─ LeftToe_End
└─ RightUpLeg ─ RightLeg ─ RightFoot ─ RightToeBase ─ RightToe_End

fingers: LeftHand{Thumb,Index,Middle,Ring,Pinky}{1,2,3,4}
         the 4 is the tip marker, not a knuckle

        
Files downloaded from Mixamo prefix every bone with mixamorig:. Strip it, or keep it and stay consistent — but note that three.js sanitises the colon away on load, so mixamorig:Hips arrives as mixamorigHips.

      


      

        quadruped — the same convention, applied to four legs
        
Hips
├─ Spine
│  └─ Spine1
│     └─ Spine2
│        ├─ Neck
│        │  └─ Neck1               only if the neck is long
│        │     └─ Head
│        │        ├─ LeftEar ─ LeftEar1
│        │        ├─ RightEar ─ RightEar1
│        │        └─ Jaw
│        ├─ LeftShoulder  ─ LeftArm  ─ LeftForeArm  ─ LeftHand
│        └─ RightShoulder ─ RightArm ─ RightForeArm ─ RightHand
├─ LeftUpLeg  ─ LeftLeg  ─ LeftFoot  ─ LeftToeBase
├─ RightUpLeg ─ RightLeg ─ RightFoot ─ RightToeBase
└─ Tail ─ Tail1 ─ Tail2 ─ Tail3

        
Nothing is renamed here — the front legs are Mixamo's arm chain and the hind legs are its leg chain, which is also anatomically right: Shoulder is the scapula, Hand and ToeBase are the paws, and on a digitigrade animal Foot is the hock held vertical. Extras Mixamo has no word for get the same numbering style: Tail, LeftEar, Jaw. A dragon whose wings are its forelimbs uses the arm chain and the LeftHand* finger names for the wing fingers; wings on top of four legs need an invented LeftWing ─ LeftWing1.

      


      
Both trees are what the tools speak. tools/creatures/mixamo-rig.mjs holds the one hierarchy, and it is what the rig editor's dropdowns offer and what scripts/check-rig-edit.mjs gates.


      
Mixamo itself is humanoid-only: there is no quadruped auto-rigger and no quadruped clips, so on an animal the tree above buys one convention rather than access to a library. The rig editor's preview still plays the Quaternius pack, translating its names through QUATERNIUS_TO_MIXAMO at playback rather than baking them into the rig.


      
bring it back

      
    
        
  • File > Export > glTF 2.0, format glTF Binary (.glb), with Animation ticked.
    • 
        
  • Save it into the folder above as anim-<name>.glb — anim-walk.glb, anim-idle.glb. Anything matching anim-*.glb is picked up automatically; the clip dropdown labels it with the middle part.
    • 
        
  • One clip per file. The preview plays the first animation in a .glb and ignores the rest, so four actions in one export shows up as one clip.
    • 
        
  • Export mesh and armature and action together. Each file is loaded on its own here, so a clip with no skin in it has nothing to move.
    • 
        
  • Hit refresh (or re-pick the creature) to see it in the dropdown.
    • 
      


      
if you change the skeleton

      
    
        
  • It rides inside each anim-*.glb. There is no separate skeleton file to keep in sync.
    • 
        
  • Do not write it back to rig.glb (Tripo's paid artifact, never overwritten) or rig-fixed.glb (regenerated from rig.glb + rig-edit.json every time you save in rig-edit — your Blender edit would vanish on the next save).
    • 
        
  • Past that point Blender owns the skeleton and rig-edit.json stops describing it. Pick one owner; editing in both is how the names drift apart.
